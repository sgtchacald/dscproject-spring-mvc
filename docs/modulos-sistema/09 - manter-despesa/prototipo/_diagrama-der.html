DER — Manter Despesa

Subconjunto do DER do Documento 0 — QUADRO_DESCRITIVO_10 (DESPESAS, com auto-relacionamento DESP_ID_PARCELA_PAI), _11 (DESPESAS_USUARIO), _5 (CONTAS), _6 (CARTOES_CREDITO), _3 (CATEGORIAS), _8 (FATURAS_CARTAO) e _2 (USUARIOS). Este documento não cria tabela nova nem faz ALTER TABLE.

USUARIOS

  • USU_ID (PK)
  • USU_NOME · USU_EMAIL (UK)
  • dono via CONTAS/CARTOES_CREDITO
  • co-participante — DESPESAS_USUARIO.USU_ID
  • audit_*

CONTAS

  • CTA_ID (PK)
  • CTA_DESCRICAO · CTA_TIPO {…|CARTEIRA}
  • USU_ID (FK → USUARIOS) NOT NULL
  • âncora de dono — DESP.CTA_ID (RN02, RN03)
  • dinheiro em espécie = conta CARTEIRA (Obs. 2a)
  • audit_*

CARTOES_CREDITO

  • CACR_ID (PK)
  • CACR_DESCRICAO
  • USU_ID (FK → USUARIOS) NOT NULL
  • âncora alternativa — DESP.CACR_ID (RN02, RN03)
  • audit_*

CATEGORIAS

  • CATE_ID (PK)
  • CATE_NOME
  • CATE_APLICA_A {DESPESA|RECEITA|AMBOS}
  • só leitura aqui — documento 04 (SB03)

DESPESAS

  • DESP_ID (PK)
  • DESP_NOME · DESP_DESCRICAO
  • DESP_VALOR DECIMAL(15,2) — > 0 (RN05)
  • DESP_VALOR_TOTAL_COMPRA DECIMAL(15,2) NULL
  • DESP_COMPETENCIA CHAR(7) yyyy-MM (YearMonthConverter)
  • DESP_DT_LANCAMENTO · DESP_DT_VENCIMENTO · DESP_DT_PAGAMENTO
  • DESP_FL_PARCELADA · DESP_NRO_PARCELA · DESP_QTD_PARCELAS
  • DESP_ID_PARCELA_PAI (FK → DESPESAS, self) NULL
  • DESP_MEIO_PAGAMENTO {DINHEIRO|DEBITO|CREDITO|PIX|BOLETO|TRANSFERENCIA}
  • DESP_IND_STATUS_PAGAMENTO {NAO|SIM|NAO_SE_APLICA}
  • DESP_FL_PAGAMENTO_FATURA BOOLEAN
  • DESP_ORIGEM {MANUAL|OPEN_FINANCE|IMPORTACAO} default MANUAL
  • CTA_ID (FK → CONTAS) NULLABLE — XOR com CACR_ID (RN03)
  • CACR_ID (FK → CARTOES_CREDITO) NULLABLE
  • FTCA_ID (FK → FATURAS_CARTAO) NULL — doc. 11
  • CATE_ID (FK → CATEGORIAS) NULLABLE
  • audit_* — @Audited (Hibernate Envers)

DESPESAS_USUARIO

  • DESP_ID + USU_ID (FKs) — UNIQUE
  • DEPU_VALOR DECIMAL(15,2) — fatia do co-participante
  • DEPU_IND_STATUS_PAGAMENTO {SIM|NAO|NAO_SE_APLICA}
  • DEPU_DT_ACERTO DATE NULL
  • soma das fatias ≤ DESP_VALOR (RN17)
  • audit_*

FATURAS_CARTAO

  • FTCA_ID (PK)
  • ciclo ABERTA → FECHADA → PAGA
  • DESP.FTCA_ID aponta para cá — doc. 11
  • audit_*
DESPESAS: CRUD + parcelamento (série auto-relacionada por DESP_ID_PARCELA_PAI, RN12/RN13/RN14) + baixa de pagamento (RN21), sempre no escopo do USU_ID da conta OU do cartão (RN02).

A âncora conta-XOR-cartão (RN03) é validada no serviço — as duas FKs continuam anuláveis no schema.

DESPESAS_USUARIO é o rateio entre usuários reais (RN15-RN20); FATURAS_CARTAO e o vínculo FTCA_ID são do documento 11 — aqui FTCA_ID fica sempre nulo (RN23).
