USUARIOS

CONTAS

  • CTA_ID (PK)
  • CTA_DESCRICAO VARCHAR(100) — única por usuário (RN03)
  • CTA_TIPO VARCHAR(20) {CORRENTE|POUPANCA|INVESTIMENTO|CARTEIRA}
  • CTA_AGENCIA VARCHAR(30) · CTA_NUMERO VARCHAR(30)
  • CTA_MOEDA CHAR(3) DEFAULT 'BRL'
  • CTA_SALDO DECIMAL(15,2) DEFAULT 0.00
  • CTA_SALDO_SINCRONIZADO_EM DATETIME(6) NULL
  • CTA_NOME_GERENTE · CTA_TEL_GERENTE
  • CTA_FL_ATIVO BOOLEAN DEFAULT TRUE
  • CTA_FL_CONSIDERA_SALDO BOOLEAN DEFAULT TRUE
  • INFI_ID (FK → INSTITUICOES_FINANCEIRAS) NOT NULL
  • USU_ID (FK → USUARIOS) NOT NULL
  • audit_* — @Audited (Hibernate Envers)

TRANSACOES_BANCARIAS

  • TRBA_ID (PK)
  • CTA_ID (FK → CONTAS) NOT NULL
  • conta com transação nunca é excluível (RN07)
  • audit_data_exclusao (exclusão lógica)

RECEITAS / DESPESAS /
INVESTIMENTOS / CARTOES_CREDITO

  • <PK própria>
  • CTA_ID (FK → CONTAS) NULLABLE
  • CARTOES_CREDITO: conta de débito da fatura
  • contagem de uso — C4 (soma das cinco)
  • audit_data_exclusao (exclusão lógica)
CONTAS: CRUD + ajuste de saldo + desativação, sempre no escopo do USU_ID autenticado (RN02). INFI_ID é imutável após a criação (RN06).

A trava de exclusão (RN07 / C4) atravessa as cinco FKs CTA_ID. TRANSACOES_BANCARIAS.CTA_ID é NOT NULL — sempre bloqueia; as demais são NULLABLE e o bloqueio depende do parâmetro CONTA_EXCLUSAO_BLOQUEIA_EM_USO.
